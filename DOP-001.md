# DOP-001 — Blog / CMS Platform

**PIC (Product Owner / Overall):** Dat Pham & Trung (co-owned)

**Problem statement**
Small teams writing blog posts struggle with having no central place to draft and categorize their content, causing drafts to be scattered and making it impossible for readers to filter published work by category.

**Solution**
Our Blog / CMS Platform solves this by providing a single shared workspace where Authors can draft, categorize (one category per post), and publish content through a clear status lifecycle (DRAFT → PUBLISHED → ARCHIVED), while allowing Readers to browse filtered posts and leave comments.

**Scope decisions**
- Single shared workspace application (not a multi-tenant SaaS) — all Authors and posts live in one shared space, no per-team data isolation.
- One category per post (`categoryId` is singular and nullable).
- Explicit 3-state post lifecycle: `DRAFT → PUBLISHED → ARCHIVED`.

**Users and use cases**
- **Author** — register/login, create/edit draft posts, create categories, assign categories to posts, publish/unpublish posts.
- **Reader** — register/login (required to comment), browse/filter published posts by category, read a single published post, leave/edit/delete their own comments.
- **Admin** — internal moderation persona with elevated platform oversight: can moderate/archive any policy-violating post, delete any comment, and update any user's role. The first Admin account is seeded automatically at user-service startup from `INITIAL_ADMIN_EMAIL` / `INITIAL_ADMIN_PASSWORD` if no users exist yet (see IRD-001).

**Services and ownership**
- **gateway** (PIC: shared) — single entry point; routes requests; validates JWT on protected routes; forwards authenticated user ID and role downstream via `X-User-Id` and `X-User-Role`. Owns no data.
- **user-service** (PIC: Dat Pham) — owns user accounts, registration, login, role management (including admin role updates), and JWT issuance.
- **content-service** (PIC: Trung) — owns posts, categories, and comments.
- **frontend** (PIC: shared) — React SPA (Vite), the only client-facing UI. Calls `gateway` directly from the browser over its public host port; owns no data of its own, no server-side logic. Satisfies the Day 9 project-floor requirement ("frontend + backend + database").
- **PostgreSQL** (Storage, not a service) — persistent storage; logical schema separation: `user_db` (user-service), `content_db` (content-service).

**Acceptance criteria**
1. A user (Author or Reader) can register and login, receiving a JWT token with their assigned role
2. A newly self-registered user is always assigned the READER role — elevated roles cannot be self-granted (the only exception is the automated first-Admin bootstrap at deployment time)
3. An Author can create a draft post with a title and body
4. An Author can create a category and assign it to their post
5. An Author can publish their own post, and unpublish it back to draft; an Admin can archive any post for moderation
6. Anyone (no login) can browse published posts, optionally filtered by category
7. Anyone (no login) can read a single published post; a non-published post is visible only to its owning author or an admin, and returns 404 (not 403) to anyone else
8. A logged-in user can leave a comment on a post, and edit/delete their own comment; an Admin can delete any comment for moderation
9. All API endpoints return standard JSON and standard HTTP status codes with a consistent error payload structure

**How the agent uses this DOP**
When implementing any Sprint 1 task tied to this DOP, the agent must:
1. Read this DOP to understand the overall goal, service ownership, and PIC assignment
2. Read the linked IRD (IRD-001/002/003/004) for the exact API contract, data model, and security rules of the service being implemented
3. Verify each implementation decision against the Scope and Acceptance Criteria above
4. Never let a service accept a client-supplied `role` on public registration, and never let `GET /posts/:id` leak non-published content — these are settled security rules, not open decisions
