# DOP-001 — Blog / CMS Platform

**Problem statement**
Small teams and solo creators writing blog posts have no central place to draft, categorize, and organize their content — drafts are scattered and there's no way to filter published work by category.

**Solution**
Our system gives teams a platform to write, categorize, and publish posts, with category-based filtering and reader comments.

**Users and use cases**
- **Author** — register/login, create and edit a draft, create categories, assign a category to posts, publish/unpublish a post
- **Reader** — register/login (required to comment), browse/filter published posts by category, read a post, leave/edit/delete their own comment

**Services and ownership**
- **api-gateway** — single entry point; routes requests; validates JWT on protected routes; forwards authenticated user ID and role downstream via `X-User-Id` and `X-User-Role`. Owns no data.
- **content-service** — owns posts, categories, and comments
- **user-service** — owns user accounts, registration, login, role management, and JWT issuance
- **PostgreSQL** — persistent storage, separate schema per service

**Acceptance criteria**
- A user (Author or Reader) can register and login, receiving a JWT token with their assigned role
- A newly self-registered user is always assigned the `READER` role — elevated roles cannot be self-granted
- An Author can create a draft post with a title and body
- An Author can create a category and assign it to their post
- An Author can publish their own post, and unpublish it back to draft
- Anyone (no login) can browse published posts, optionally filtered by category
- Anyone (no login) can read a single published post; a non-published post is visible only to its owning author or an admin
- A logged-in user can leave a comment on a post, and edit/delete their own comment
- All API endpoints return standard JSON and standard HTTP status codes with a consistent error payload structure
