# DOP-003 — Orchestration (Kubernetes + Helm)

**Project:** Blog / CMS Platform · **PIC:** Trung & Dat Pham (co-owned)
**Status:** ACTIVE · **Last audited:** 2026-10-17 (Day 21)

## 1. Objective
The whole Blog/CMS stack runs on Kubernetes from **one** manifest set in git, comes up healthy on a fresh cluster (minikube / Docker Desktop or EKS) with no manual step, and never needs a credential committed to make that happen.

## 2. In scope
- **Single manifest set** (decided 2026-10-17, Trung + Dat): Kustomize base + overlay in this repo.
  - `k8s/base/` — the reference set (Dat's Day 15 manifests), runs as-is locally: `kubectl apply -k k8s/base`.
    - Namespace `blogcms` (`namespace.yaml`; `namespace: blogcms` on every object).
    - Deployments: `user-service`, `content-service`, `gateway`, `frontend` (replicas 2); `postgres` (replicas 1, `Recreate`, PVC `postgres-pvc`).
    - Per-service ConfigMaps (`*-config`) and Secrets (`*-credentials`, created by `k8s/create-secrets.sh`, **never committed**).
    - `postgres-initdb` ConfigMap creates `user_db` + `content_db` on first init.
    - Ingress `blogcms-ingress` (ingress-nginx), **host-based**: `blogcms.local` → `frontend:5173`, `api.blogcms.local` → `gateway:3000` (gateway routes have no `/api` prefix).
    - All Services `ClusterIP`; Ingress is the only entry point.
  - `k8s/overlays/eks/` — EKS deltas only: ECR images, `imagePullPolicy: IfNotPresent`, replicas 1 for `t3.small` (DOP-004). `kubectl apply -k k8s/overlays/eks`.
  - The old EKS set in `proops2026/k8s/blogcms/` is retired (deleted 2026-10-17).

## 3. Out of scope
- Autoscaling for blogcms services (HPA practice on Day 14 used a separate `web` app). Postgres is never autoscaled.
- Packaging our own services as a Helm chart (raw manifests + Kustomize for now).
- Redis / any cache — Helm release from Day 16 removed by decision 2026-10-17 (no service used it; DOP-001 Out of scope).
- NetworkPolicies, service mesh, GitOps controller — later weeks.

## 4. Acceptance criteria

| # | Criterion | Check | Status |
|---|---|---|---|
| AC-1 | Exactly one manifest set is the deployment source of truth | `k8s/base` + `k8s/overlays/eks` only; `kubectl kustomize` builds both | DONE 2026-10-17 — sets merged, Trung's set deleted |
| AC-2 | Every container has CPU + memory requests and limits | `grep -L 'limits:' k8s/base/*-deployment.yaml` empty | DONE |
| AC-3 | Every container has readiness + liveness probes | `grep -c 'Probe:' k8s/base/*-deployment.yaml` = 2 each | DONE |
| AC-4 | Workloads run in a dedicated namespace, never `default` | `grep -L 'namespace: blogcms' k8s/base/*.yaml` lists only `namespace.yaml`, `kustomization.yaml` | DONE 2026-10-17 |
| AC-5 | A fresh cluster reaches all Pods `Running` + Ready with no manual step | `create-secrets.sh` + `kubectl apply -k k8s/base` on an empty cluster | DONE 2026-10-17 (Docker Desktop, 9/9 Pods Ready) · EKS overlay not yet run |
| AC-6 | No credential is committed | `grep -rl 'kind: Secret' k8s/` empty | DONE |
| AC-7 | Backends and postgres are never exposed outside the cluster | `grep -h 'type:' k8s/base/*-service.yaml` all ClusterIP | DONE |
| AC-8 | Admin bootstrap is safe with replicas > 1 | cold start with 2 user-service replicas, no Pod `Error` | ACTIVE — TOCTOU race seen Day 15; not reproduced 2026-10-17 (rolling start), code fix still due 2026-10-21 |
| AC-9 | Helm releases install from a committed values file, never `--set` only | `helm get values <release>` = committed file | DEFERRED — no Helm release in the project after Redis removal; applies to the next chart (IRD-008) |
