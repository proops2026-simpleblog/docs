# IRD-007 — Kubernetes Deployment Standards

**PIC:** Dat Pham & Trung (shared)
**Implements:** DOP-003 Orchestration
**Status:** ACTIVE · **Last updated:** 2026-10-17 (Day 21)

## 1. Context
`k8s/` (Day 15, Dat) and `proops2026/k8s/blogcms/` (Day 15–17, Trung, EKS variant) were built separately and diverged: namespace, postgres kind, ingress routing and secret handling all differ. CI (Day 24) will apply manifests on every merge, so there must be one rule set a reviewer and the agent check against.

**Decision 2026-10-17 (Trung + Dat):** Dat's set is the base (`k8s/base/`); from Trung's set only the namespace, ECR image paths and EKS replica count were kept (`k8s/overlays/eks/`); ingress stays host-based; Trung's set is deleted.

## 2. Inputs
- Images per IRD-006.
- Per-service ConfigMap `<service>-config` (non-sensitive: `PORT`, service URLs, `VITE_API_BASE_URL`, `INITIAL_ADMIN_EMAIL`).
- Per-service Secret `<service>-credentials` (sensitive: `DATABASE_URL`, `JWT_SECRET`, `INITIAL_ADMIN_PASSWORD`, postgres creds) — created by `k8s/create-secrets.sh`, **never committed**.

## 3. Outputs
- Running workloads in namespace `blogcms`, reachable through Ingress hosts `blogcms.local` (frontend) and `api.blogcms.local` (gateway).

## 4. Manifest rules

| Rule | Required | Status 2026-10-17 |
|---|---|---|
| File layout | `k8s/base/<service>-{configmap,deployment,service}.yaml`; environment deltas only in `k8s/overlays/<env>/kustomization.yaml` | ✅ |
| Apply | `kubectl apply -k k8s/base` (local) or `-k k8s/overlays/eks`; never a bare `kubectl apply -f` without namespace | ✅ |
| Namespace | `blogcms` — set in `kustomization.yaml` **and** in every file's `metadata.namespace` | ✅ |
| Labels | `app: <service>` on Deployment, Pod template, Service selector | ✅ |
| Resources | requests + limits, CPU and memory, every container | ✅ |
| Probes | readiness + liveness `httpGet /health` (frontend: `tcpSocket`; postgres: `pg_isready`) | ✅ |
| Config vs Secret | "Would leaking it to a CI log / PR diff need an incident review?" yes → Secret | ✅ |
| Secrets in git | Never — `k8s/create-secrets.sh` (idempotent, reuses existing values, never rotates) or SealedSecret | ✅ |
| Exposure | Every Service `ClusterIP`; Ingress is the only entry | ✅ |
| Ingress | Host-based: `blogcms.local`, `api.blogcms.local`; no path rewrite | ✅ |
| DB bootstrap | `postgres-initdb` ConfigMap creates `user_db`, `content_db` | ✅ |
| Postgres | 1 replica, `Recreate`, PVC; never autoscaled | ✅ |
| Image | Commit-SHA tag (IRD-006) | ❌ base `:local`, EKS overlay `:v1` — CI fixes Day 24 |

## 5. Acceptance criteria
- AC-1: Every container has requests + limits.
- AC-2: Every container has readiness + liveness probes.
- AC-3: Every object is in namespace `blogcms`.
- AC-4: No `kind: Secret` file is committed.
- AC-5: Every Service is `ClusterIP`.
- AC-6: On an empty cluster, all Pods reach `Running` + Ready with no manual `kubectl exec`.
- AC-7: `JWT_SECRET` is identical for gateway and user-service (token issued by one validates at the other).
- AC-8: Both variants build: `kubectl kustomize k8s/base` and `kubectl kustomize k8s/overlays/eks` exit 0.

## 6. Dependencies
ingress-nginx `controller-v1.15.1` · a default StorageClass (Docker Desktop `standard` / minikube `standard`, EKS `gp2-csi`) · IRD-003 (routing, trust boundary) · IRD-006 (images) · DOP-004 (EKS node capacity)

## 7. Tests
```bash
cd k8s/base
grep -L 'limits:' *-deployment.yaml                         # no output                         (AC-1)
grep -c 'Probe:' *-deployment.yaml                          # 2 each                            (AC-2)
grep -L 'namespace: blogcms' *.yaml                         # only namespace.yaml, kustomization.yaml (AC-3)
grep -rl 'kind: Secret' ..                                  # no output                         (AC-4)
grep -h 'type:' *-service.yaml | sort | uniq -c             # only ClusterIP                    (AC-5)
cd ../.. && kubectl kustomize k8s/base >/dev/null && kubectl kustomize k8s/overlays/eks >/dev/null && echo ok   # (AC-8)

# live (cluster up)
k8s/create-secrets.sh && kubectl apply -k k8s/base
kubectl get pods -n blogcms                                 # all Running, READY 1/1            (AC-6)
kubectl exec -n blogcms deploy/postgres -- psql -U postgres -lqt | cut -d'|' -f1 | grep -wE 'user_db|content_db'   # 2 lines (AC-6)
diff <(kubectl get secret gateway-credentials -n blogcms -o jsonpath='{.data.JWT_SECRET}') \
     <(kubectl get secret user-service-credentials -n blogcms -o jsonpath='{.data.JWT_SECRET}') && echo same   # same (AC-7)
```
Result 2026-10-17 (Docker Desktop, K8s 1.36.1): AC-1 ✅ · AC-2 ✅ · AC-3 ✅ · AC-4 ✅ · AC-5 ✅ · AC-6 ✅ (9/9 Pods Ready, both DBs present) · AC-7 ✅ · AC-8 ✅.

**Local cluster note:** Docker Desktop's kind node has its own containerd — host `docker build` images must be imported into the node (`imagePullPolicy: Never`). On K8s 1.36, an image whose ID was earlier pulled *with registry credentials* (e.g. the same build pushed to ECR and pulled on this node) is refused for pods without those credentials (`ErrImageNeverPull`, kubelet `EnsureSecretPulledImages`). Fix used: build the local image with `--label org.opencontainers.image.revision=<sha>` so it has its own image ID.
