# DOP-006 — CI/CD

**Project:** Blog / CMS Platform · **PIC:** Trung & Dat Pham (co-owned)
**Status:** ACTIVE · **Last audited:** 2026-10-29 (Sonar scope + secrets, Dat)

## 1. Objective
No change reaches `main` of a service repo unless it lints, passes its tests and builds an image on a clean runner. Every image pushed from `main` is tagged with the commit it was built from, and the pipeline proves that the cluster runs exactly that image.

## 2. In scope
- GitHub Actions in the 4 service repos: `content-service`, `user-service`, `gateway`, `frontend`.
- One `.github/workflows/ci.yml` per repo: lint ∥ test → build-image → deploy, plus `sonar` after `test`.
- Code quality: SonarCloud Quality Gate on new code, fed by the `test` job's coverage (Day 26).
- Registry: GHCR, `ghcr.io/proops2026-simpleblog/<service>:<sha7>`, pushed from `main` only.
- CI deploy target: a throwaway kind cluster per run, built from `docs/k8s/base` + a generated CI overlay (IRD-007).
- Merge gate: the "Protect main" ruleset requires the CI jobs as status checks, managed by `proops2026/scripts/protect-main.sh`.

## 3. Out of scope
- Deploy to EKS and AWS auth (OIDC → ECR) — DOP-004 / IRD-009, Day 26.
- Image vulnerability scanning (Trivy) — DOP-002 §3, Day 25. (Static code analysis moved in scope: §2.)
- Jenkins variant of the pipeline — Day 25 lab, not a production path.
- Multi-environment promotion (dev → staging → prod) — Week 6.
- Image signing, SBOMs, multi-arch builds.
