# IRD-001 — user-service

**Scope:** Covers DOP ACs: registration, login, role management. Depends on: none.

**Tech stack:** Node.js (Express) + bcrypt + JWT

**API contract**
```text
POST /auth/register  { email, password }        → 201 { id, email, role }
                                                 → 400 invalid email format
                                                 → 409 email already exists

POST /auth/login     { email, password }        → 200 { token, expiresIn, user: { id, email, role } }
                                                 → 401 invalid credentials

GET  /health                                    → 200 { status: "ok", service: "user-service" }
```

**Data model**
```sql
User {
  id           UUID primary key default gen_random_uuid()
  email        VARCHAR(255) not null unique
  passwordHash VARCHAR(255) not null
  role         VARCHAR(20) not null default 'READER' -- ENUM: READER, AUTHOR, ADMIN
  createdAt    TIMESTAMP default now()
  updatedAt    TIMESTAMP default now()
}
```

**Validation rules**
- Email must be valid email format and globally unique (case-insensitive check)
- Password: required field, minimum 6 characters
- **Role assignment (security rule):** `POST /auth/register` does NOT accept a `role` field from the client. The server always forces `role = READER` on self-registration, regardless of any `role` value present in the request body. `AUTHOR` and `ADMIN` roles can only be granted afterward by an existing `ADMIN` via a separate, authenticated role-management action — never through public registration.
- JWT expiry: 24h; payload includes `{ sub: id, email: email, role: role }`; secret configured via environment variable `JWT_SECRET` (never hardcoded)

**Test requirements**
- Register: success (201, role always `READER`) + invalid email format (400) + duplicate email (409)
- Register: request body includes `role: "ADMIN"` → response role is still `READER` (privilege-escalation regression test)
- Login: success (200 with JWT) + wrong password / non-existent user (401)
- Health check: returns status "ok" (200)
