# DOP-002 — Containerization

**Project:** Blog / CMS Platform · **PIC:** Trung & Dat Pham (co-owned)
**Status:** ACTIVE · **Last audited:** 2026-10-14 (Day 21)

## 1. Objective
Every Blog/CMS service ships as a small, non-root, reproducible image whose tag points back to exactly one git commit, so any running Pod can be traced to its source code.

## 2. In scope
- One Dockerfile per service repo: `gateway`, `user-service`, `content-service`, `frontend`.
- Base image `node:20-alpine` for all four; `postgres:16-alpine` used as-is for the database.
- Local registry path: `minikube image build -t <service>:local` + `imagePullPolicy: Never` (`k8s/`, see `memory/kubernetes-project.md` §5).
- Cloud registry: AWS ECR, account `868737222758`, region `eu-west-2`, one repository per service.
- Tagging tool: `proops2026/scripts/deploy.sh` tags with `git rev-parse --short HEAD`.

## 3. Out of scope
- Image vulnerability scanning — deferred to Day 25 (SonarQube / Trivy in CI).
- Image signing, SBOMs, multi-arch builds.
- Production Nginx build for `frontend` (Vite dev server only, IRD-004).

## 4. Acceptance criteria

| # | Criterion | Check | Status |
|---|---|---|---|
| AC-1 | Backend Dockerfiles (`gateway`, `user-service`, `content-service`) are multi-stage | `grep -c '^FROM' <repo>/Dockerfile` ≥ 2 | DONE (2/2/2) |
| AC-2 | Every image runs as non-root | `grep '^USER' */Dockerfile` — 4 lines, none root | DONE |
| AC-3 | No `latest` base image | `grep '^FROM' */Dockerfile \| grep -i latest` empty | DONE |
| AC-4 | Shipped image has production deps only | `docker run --rm <img> sh -c 'ls node_modules \| grep -E "^(jest\|nodemon)$"'` empty | ACTIVE (not yet verified) |
| AC-5 | Every image deployed to a cluster is tagged with a commit SHA | `kubectl get deploy -o jsonpath='{..image}'` tags match `^[0-9a-f]{7}$` | ACTIVE — `k8s/` uses `:local`, EKS set used `:v1`; neither maps to a commit |
| AC-6 | `frontend` image is multi-stage | — | ACTIVE — single-stage dev image, deferred with the Nginx build |
| AC-7 | DB-owning services run Knex migrations idempotently at start (`npm run migrate && npm start`) | read `CMD` in user-service / content-service Dockerfile | DONE |

## 5. Tech stack
Docker BuildKit · `node:20-alpine` · `postgres:16-alpine` · minikube image builder · AWS ECR (`868737222758.dkr.ecr.eu-west-2.amazonaws.com/<service>`)
