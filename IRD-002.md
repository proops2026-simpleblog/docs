# IRD-002 — content-service

**PIC:** Trung

**Scope:** Covers DOP-001 ACs 3, 4, 5, 6, 7, 8, 9. Depends on: user-service (author/user IDs and roles passed via headers only — no DB foreign key across service boundary).

**Tech stack:** Node.js (Express) + ORM (e.g. Prisma / Knex)

## API Contract

```text
POST   /posts                [auth]  { title, body, categoryId? }
                                     -> 201 { id, title, status, categoryId, authorId, createdAt }
                                     -> 400 missing title/body . 401 no/invalid token

PATCH  /posts/:id            [auth]  { title?, body?, categoryId?, status? }
                                     -> 200 { id, status, updatedAt }
                                     -> 401 no/invalid token . 403 not owning author . 404 not found
                                     (status may transition DRAFT->PUBLISHED, PUBLISHED->DRAFT, or (owning author or ADMIN) -> ARCHIVED for moderation/soft-delete)

GET    /posts                        ?categoryId= &status=PUBLISHED (default)
                                     -> 200 [{ id, title, categoryId, authorId, publishedAt }]
                                     (unpaginated for Sprint 1 -- see Known Limitations)
                                     (never returns non-PUBLISHED posts, regardless of caller)

GET    /posts/:id                    -> 200 { id, title, body, status, categoryId, authorId, comments[] }
                                        -- only if status = PUBLISHED, OR caller is the owning author (X-User-Id match), OR caller is ADMIN
                                     -> 404 not found (also returned instead of 403 when a non-owner requests a non-published post, to avoid leaking that a draft exists)

GET    /categories                   -> 200 [{ id, name }]

POST   /categories            [auth]  { name } (Author/Admin only)
                                     -> 201 { id, name }
                                     -> 400 empty name . 401 unauthenticated . 403 insufficient role . 409 duplicate name

POST   /posts/:id/comments    [auth]  { body }
                                     -> 201 { id, postId, userId, body, createdAt }
                                     -> 400 empty body . 404 post not found . 401 no/invalid token

PATCH  /comments/:id          [auth]  { body }
                                     -> 200 { id, body, updatedAt }
                                     -> 401 no/invalid token . 403 not comment's author . 404 not found

DELETE /comments/:id          [auth]  (owning user or ADMIN -- also the moderation path for removing policy-violating comments)
                                     -> 204 No Content
                                     -> 401 no/invalid token . 403 not comment's author (non-admin) . 404 not found

GET    /health                       -> 200 { status: "ok", service: "content-service" }
```

## Data Model (`content_db`)

```sql
CREATE TABLE categories (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name       VARCHAR(100) NOT NULL,
  created_at TIMESTAMPTZ  NOT NULL DEFAULT now(),
  CONSTRAINT uq_categories_name UNIQUE (name)
);

CREATE TABLE posts (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  title        VARCHAR(255) NOT NULL,
  body         TEXT         NOT NULL,
  status       VARCHAR(20)  NOT NULL DEFAULT 'DRAFT'
               CHECK (status IN ('DRAFT', 'PUBLISHED', 'ARCHIVED')),
  category_id  UUID         NULL REFERENCES categories(id) ON DELETE SET NULL,
  author_id    UUID         NOT NULL, -- cross-service ref: user-service users.id, NO FK
  published_at TIMESTAMPTZ  NULL,
  created_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
  updated_at   TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE TABLE comments (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  post_id    UUID NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  user_id    UUID NOT NULL, -- cross-service ref: user-service users.id, NO FK
  body       TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_posts_status_category ON posts (status, category_id);
CREATE INDEX idx_posts_author ON posts (author_id);
CREATE INDEX idx_comments_post ON comments (post_id);
```

## Validation Rules

- Only the owning author (`X-User-Id` match) or `ADMIN` can `PATCH` a post — 403 otherwise
- **Security rule — draft post access control:** `GET /posts/:id` returns full content only if `status = PUBLISHED`, OR requester is the owning author, OR requester is `ADMIN`. Any other caller gets `404`, never `403`, so a draft's existence is never revealed.
- `GET /posts` (list) never returns non-`PUBLISHED` posts, regardless of caller
- Category creation restricted to `AUTHOR`/`ADMIN` — 403 for `READER`; category name must be unique (409 on duplicate) and non-empty (400)
- Comment edit/delete restricted to the comment's own author or `ADMIN` — 403 otherwise; comment body cannot be empty
- **Post archiving (moderation/soft-delete):** archiving is a simple status transition (`status = 'ARCHIVED'`, `updated_at = now()`) — no audit trail (`archivedBy`/`archivedReason`) in Sprint 1; this is an accepted scope limitation, not an oversight

## Cross-Service Reference Rule

`author_id` and `user_id` store the `user-service` UUID only — no SQL foreign key constraint across the database boundary. Services remain independently deployable.

## Known Limitations (deferred, not gaps)

- `GET /posts` returns all matching results unpaginated for Sprint 1.
- Post archiving has no audit trail in Sprint 1 (accepted scope decision).

## Test Requirements

- Create draft: success (201) + missing title (400)
- Publish/unpublish/archive: success (200) + non-owner attempt (403)
- Browse/filter: returns only PUBLISHED posts by default, never returns DRAFT/ARCHIVED posts even when queried by their own author
- `GET /posts/:id` on a DRAFT post: owning author -> 200; ADMIN -> 200; any other authenticated or anonymous caller -> 404
- Category creation: success (201) + duplicate name (409) + empty name (400) + Reader role attempt (403)
- Comment: create success (201) + unauthenticated (401); edit/delete success + non-owner attempt (403); Admin delete of another user's comment succeeds (204)
