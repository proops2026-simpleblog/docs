# IRD-002 — content-service

**Scope:** Covers DOP ACs: create/edit draft, categorize, publish/unpublish, browse/filter, read, comment (+edit/delete own comment). Depends on: user-service (author/user IDs and roles passed via headers only — no DB foreign key across service boundary).

**Tech stack:** Node.js (Express) + ORM (e.g. Prisma / Knex)

**API contract**
```text
POST   /posts                🔒  { title, body, categoryId? }
                                  → 201 { id, title, status, categoryId, authorId, createdAt }
                                  → 400 missing title/body · 401 no/invalid token

PATCH  /posts/:id             🔒  { title?, body?, categoryId?, status? }
                                  → 200 { id, status, updatedAt }
                                  → 404 not found · 403 not owning author
                                  (status may transition DRAFT→PUBLISHED or PUBLISHED→DRAFT)

GET    /posts                     ?categoryId= &status=PUBLISHED (default)
                                  → 200 [{ id, title, categoryId, authorId, publishedAt }]
                                  (unpaginated for Sprint 1 — see Known Limitations)
                                  (this list endpoint only ever returns PUBLISHED posts — draft/archived posts never appear here regardless of caller)

GET    /posts/:id                 → 200 { id, title, body, status, categoryId, authorId, comments[] }  — only if status = PUBLISHED, or caller is the owning author (X-User-Id match) or ADMIN
                                  → 404 not found (also returned, instead of 403, when a non-owner requests a non-published post — to avoid leaking that a draft exists)

GET    /categories                → 200 [{ id, name }]

POST   /categories            🔒  { name } (Author/Admin only)
                                  → 201 { id, name }
                                  → 400 empty/duplicate name · 401 unauthenticated · 403 insufficient role

POST   /posts/:id/comments    🔒  { body }
                                  → 201 { id, postId, userId, body, createdAt }
                                  → 400 empty body · 404 post not found · 401 no/invalid token

PATCH  /comments/:id          🔒  { body }
                                  → 200 { id, body, updatedAt }
                                  → 403 not comment's author · 404 not found

DELETE /comments/:id          🔒
                                  → 204 No Content
                                  → 403 not comment's author · 404 not found

GET    /health                    → 200 { status: "ok", service: "content-service" }
```
🔒 = requires Bearer JWT, validated upstream by api-gateway. `X-User-Id` and `X-User-Role` forwarded in headers.

**Data model**
```sql
Post {
  id          UUID primary key default gen_random_uuid()
  title       VARCHAR(255) not null
  body        TEXT not null
  status      VARCHAR(20) not null default 'DRAFT' -- ENUM: DRAFT, PUBLISHED, ARCHIVED
  categoryId  UUID references category(id) ON DELETE SET NULL, nullable
  authorId    UUID not null -- references user-service, ID only, no DB FK constraint
  publishedAt TIMESTAMP nullable
  createdAt   TIMESTAMP default now()
  updatedAt   TIMESTAMP default now()
}

Category {
  id        UUID primary key default gen_random_uuid()
  name      VARCHAR(100) not null unique
  createdAt TIMESTAMP default now()
}

Comment {
  id        UUID primary key default gen_random_uuid()
  postId    UUID not null references post(id) ON DELETE CASCADE
  userId    UUID not null -- references user-service, ID only, no DB FK constraint
  body      TEXT not null
  createdAt TIMESTAMP default now()
  updatedAt TIMESTAMP default now()
}
```
Indexes: `CREATE INDEX idx_posts_category_status ON posts(category_id, status);`, `CREATE INDEX idx_comments_post ON comments(post_id);`

**Validation rules**
- Only the owning author (matching `X-User-Id`) or `ADMIN` role can PATCH a post — returns 403 otherwise
- **Draft post access control (security rule):** `GET /posts/:id` returns full post content only when `status = PUBLISHED`, OR the requester is the owning author (`X-User-Id` matches `authorId`), OR the requester has `X-User-Role = ADMIN`. Any other caller requesting a non-published post receives `404 Not Found` (not `403`), so that the existence of an unpublished post is never revealed to an unauthorized caller.
- `GET /posts` (list) never returns non-`PUBLISHED` posts, regardless of who is asking — browsing drafts is not supported by this endpoint for any role.
- Category creation is restricted to `AUTHOR` or `ADMIN` roles (`X-User-Role`) — returns 403 for `READER`
- Category `name` must be unique and non-empty
- Comment edit/delete is restricted to the comment's own author (`X-User-Id`) or `ADMIN` — returns 403 otherwise
- Comment body cannot be empty

**Cross-service reference rule**
`authorId` and `userId` store the `user-service` UUID only — no SQL foreign key constraint across the database boundary. Services remain independently deployable.

**Known limitations (deferred, not gaps)**
- `GET /posts` returns all matching results unpaginated for Sprint 1. Pagination (`?page=&limit=`) is deferred until data volume requires it.

**Test requirements**
- Create draft: success (201) + missing title (400)
- Publish/unpublish: success (200) + non-owner attempt (403)
- Browse/filter (`GET /posts`): returns only PUBLISHED posts by default, never returns DRAFT/ARCHIVED posts even when queried by their own author
- `GET /posts/:id` on a DRAFT post: owning author → 200; ADMIN → 200; any other authenticated or anonymous caller → 404
- Category creation: success (201) + duplicate name (400) + Reader role attempt (403)
- Comment: create success (201) + unauthenticated (401); edit/delete success + non-owner attempt (403)
