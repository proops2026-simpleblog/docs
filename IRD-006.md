# IRD-006 — Docker Image Standards

**PIC:** Trung
**Implements:** DOP-002 Containerization
**Status:** ACTIVE · **Last updated:** 2026-10-14 (Day 21)

## 1. Context
Four services were containerized by two people at different times. The Dockerfiles agree on the important rules, but the rules were never written down. Day 17 showed the cost of having no tagging rule: the running `gateway:v1` image on EKS lacked `PATCH /posts/:id`, a route git has had since `gateway@6c784a5`. This IRD writes the conventions down so the Day 23–26 CI can enforce them.

## 2. Inputs
- Service repo: `package.json`, `package-lock.json`, `src/`, and for DB-owning services `migrations/` + `knexfile.js`.
- No build args. Runtime config comes only from env vars (IRD-007); nothing environment-specific is baked into the image.

## 3. Outputs
- Image `<registry>/<service>:<git-short-sha>`:
  - minikube: `minikube image build -t <service>:$(git rev-parse --short HEAD) .`
  - cloud: `868737222758.dkr.ecr.eu-west-2.amazonaws.com/<service>:<sha>`
- One ECR repository per service, same name as its git repo.

## 4. Dockerfile contract

| Rule | Required form |
|---|---|
| Base image | `node:20-alpine` in every stage. Never `latest`. |
| Stages | `builder` (install deps) → `runtime` (final). Runtime copies only prod `node_modules`, `src/`, and if present `migrations/` + `knexfile.js`. |
| Dependencies | Lockfile-exact (`npm ci --omit=dev`) in the shipped stage. |
| User | Dedicated non-root user (`addgroup -S` / `adduser -S`), `chown` `/app`, then `USER <name>`. |
| Env | `ENV NODE_ENV=production` in runtime. No secrets in `ENV` / `ARG`. |
| Port | `EXPOSE` = service port from DOP-001. |
| Start | DB-owning services: `npm run migrate && npm start` (Knex is idempotent). Others: `node src/index.js`. |
| Tag | Short commit SHA. Never `latest`; never hand-picked labels (`v1`, `local`) for anything a cluster runs. |

Known exception: `frontend` is a single-stage Vite dev image until the Nginx build lands (DOP-002 AC-6).

## 5. Acceptance criteria
- AC-1: `gateway`, `user-service`, `content-service` Dockerfiles each have ≥ 2 `FROM` lines.
- AC-2: All 4 Dockerfiles end with a non-root `USER`.
- AC-3: No `FROM …:latest`.
- AC-4: Shipped images contain no dev dependencies (`jest`, `nodemon`).
- AC-5: Every image a cluster runs has a 7-hex-char tag that exists as a commit in the service repo.
- AC-6: `docker run --rm <img> id -u` prints a non-zero UID.

## 6. Dependencies
Docker BuildKit · minikube image builder · AWS ECR · DOP-002 · IRD-007 (how images are consumed)

## 7. Tests
```bash
# from the folder that holds the 4 service repos
grep -c '^FROM' gateway/Dockerfile user-service/Dockerfile content-service/Dockerfile   # each >= 2           (AC-1)
grep -n '^USER' */Dockerfile                                                         # 4 lines, none root   (AC-2)
grep -n '^FROM' */Dockerfile | grep -i latest                                        # no output            (AC-3)

docker build -t gw-test gateway/
docker run --rm gw-test id -u                                                        # non-zero             (AC-6)
docker run --rm gw-test sh -c 'ls node_modules | grep -E "^(jest|nodemon)$"'         # no output            (AC-4)

kubectl get deploy -A -o jsonpath='{range .items[*]}{.spec.template.spec.containers[0].image}{"\n"}{end}'
#   every blogcms tag must match ^[0-9a-f]{7}$                                                              (AC-5)
```
Result 2026-10-14: AC-1 ✅ (2/2/2) · AC-2 ✅ · AC-3 ✅ · AC-4 not yet run · AC-5 ❌ (`k8s/` uses `:local`, EKS set used `:v1`).
