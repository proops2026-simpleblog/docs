## 1. Context
Until Day 23 nothing ran the tests except our laptops. The first clean-runner run of content-service failed (`Unable to acquire a connection`, run 39385790283) because the tests silently depended on the Compose Postgres. Day 24 then built a full pipeline in content-service. Two bugs only showed up in real runs: a `pull_request` run tags the image with GitHub's temporary merge commit (`7193a9e` = "Merge 8073320 into 621fdb3"), and `rollout status` reports success on an unchanged Deployment. This IRD writes down the rules that came out of those runs, so the other 3 repos copy a verified pipeline instead of the course template.

Reference implementation: `content-service/.github/workflows/ci.yml` @ `40c914f`.

## 2. Inputs
- Service repo: `package.json` (`lint`, `test`, and for DB-owning services `migrate` scripts), `package-lock.json`, `Dockerfile` (IRD-006).
- `docs` repo: `k8s/base`, `k8s/create-secrets.sh` (IRD-007).
- No repo secrets. Org secrets only as listed in §8 (`SONAR_TOKEN`, Day 26). Otherwise `GITHUB_TOKEN` (job-scoped permissions) only.
- Org variables (not secret): `SONAR_HOST_URL`, `SONAR_ORGANIZATION`.

## 3. Outputs
- Required status checks on `main`: `lint`, `test`, `build-image`, `deploy`.
- `main` runs: image `ghcr.io/proops2026-simpleblog/<service>:<sha7>`.
- PR runs: an `image.tar` artifact (retention 1 day), never pushed.

## 4. Workflow contract

| Rule | Required form | Why |
|---|---|---|
| File | `.github/workflows/ci.yml`, `name: CI` | One file per repo; the check names come from job ids |
| Triggers | `pull_request` + `push: branches: [main]` + `workflow_dispatch` | Unfiltered `push` + `pull_request` runs twice per commit |
| Concurrency | `group: ci-${{ github.ref }}`, `cancel-in-progress: ${{ github.event_name == 'pull_request' }}` | Cancel superseded PR runs; never cancel a `main` push |
| Token | Workflow `permissions: contents: read`; `packages: write` on `build-image` only | Repo default stays read; least privilege per job |
| Runner | `ubuntu-24.04`, never `-latest` | Reproducible image |
| Timeouts | `timeout-minutes` on every job (lint 5, test 10, build 15, deploy 15) | Default is 360 min |
| Shell | `defaults: run: shell: bash` where pipes are used | Default `bash -e` has no `pipefail` |
| Toolchain | `actions/setup-node@v7`, `node-version: '20'`, `cache: npm` | = Dockerfile `node:20-alpine` (IRD-006), not the laptop's Node |
| Install | `npm ci` | Lockfile-exact |
| Action pins | First-party `actions/*` → major tag (`@v7`). Third-party → full commit SHA + version comment | A tag can be moved; a SHA can't |

## 5. Job graph

```
lint ─┐                     parallel, no needs:
test ─┤  postgres service → migrate → test
      ▼  needs: [lint, test]
build-image   PR: tarball artifact · main: push to GHCR
      ▼  needs: [build-image]
deploy        kind → apply → rollout → assert image

test ──▶ sonar   needs: [test]; reads the coverage artifact; skipped while SONAR_HOST_URL is unset and on fork PRs
```

- `test` does **not** need `lint`: a serial edge hides a test failure behind a lint failure and slows every run.
- `lint`: `npm run lint` = `eslint . --max-warnings 0`. A repo without lint tooling adds it before it gets CI.
- `test` (DB-owning services): service `postgres:16-alpine`, `POSTGRES_HOST_AUTH_METHOD: trust`, `pg_isready` health check, `DATABASE_URL` env, `npm run migrate` before `npm test`. No passwords: the DB is thrown away.

## 6. Image rules (extends IRD-006)

| Rule | Required form |
|---|---|
| Name | `ghcr.io/${GITHUB_REPOSITORY,,}:${GITHUB_SHA::7}` — lowercase, 7-char SHA, no `latest` |
| Who pushes | `push` to `main` and `workflow_dispatch` only. On `pull_request`, `GITHUB_SHA` is a temporary merge commit, so PRs build `type=docker` to a tarball and `kind load` it |
| Cache | `cache-from: type=gha`, `cache-to: type=gha,mode=max` |
| Evidence | Verify by **digest**, not tag: push log digest = `docker pull` digest |

## 7. Deploy job (CI verification, not an environment)
1. Checkout `docs`, create a kind cluster `ci-$GITHUB_RUN_ID`.
2. `bash docs/k8s/create-secrets.sh` (random values; `bash` because the file is committed `100644`).
3. PR: download + `kind load image-archive`. `main`: `ghcr-pull` imagePullSecret (GHCR package is private).
4. Generate `k8s/overlays/ci`: `resources: ../../base`, `images:` swap to the built image, `imagePullPolicy: IfNotPresent`, remove the other services.
5. `kubectl apply -k`, then `rollout status` for postgres and the service.
6. **Fail** the job unless every Pod of the service runs `needs.build-image.outputs.image`. `rollout status` alone is not proof.
7. `if: failure()` diagnose step: `kubectl get/describe/logs`.

## 8. Secrets and merge gate
- Never put a secret in YAML, code or docs (the repos are public). Map a secret into the one step that needs it via `env:`, never `${{ secrets.X }}` inside `run:`.
- Never use `pull_request_target` with a checkout of the PR head.
- Test-only credentials (`JWT_SECRET`, admin password for the throwaway DB) are generated per run with `openssl rand`, `::add-mask::`ed, then written to `$GITHUB_ENV`. No credential-shaped literal in YAML, logs show `***`.
- Allowed org secrets: `SONAR_TOKEN` (Sonar analysis only; mapped via `env:` into the scan step only). Any new one needs a row in §9 first.
- AWS (Day 26): GitHub OIDC → IAM role, `id-token: write` on that job only, role ARN as an org **variable**. No access keys.
- "Protect main" is changed only through `scripts/protect-main.sh` (`REQUIRED_CHECKS`, `REQUIRED_APPROVALS`, `DRY_RUN`). UI edits are overwritten.
- Add required checks to a repo **only after** its `ci.yml` is on `main`. Otherwise every PR waits forever on "Expected — waiting for status".

## 10. Acceptance criteria
- AC-1: `ci.yml` follows §4 (triggers, concurrency, permissions, runner, timeouts, pins).
- AC-2: Job ids are exactly `lint`, `test`, `build-image`, `deploy`; `build-image` needs both `lint` and `test`.
- AC-3: A `pull_request` run pushes nothing to GHCR; a `main` run pushes exactly `<service>:<sha7>`.
- AC-4: `deploy` fails when the running image ≠ the built image.
- AC-5: The repo has 0 Actions secrets (org secrets only per §8) and the repo default token permission is `read`.
- AC-6: "Protect main" requires the 4 checks, applied by `protect-main.sh`.

## 11. Tests
```bash
R=proops2026-simpleblog/<repo>
gh api repos/$R/contents/.github/workflows/ci.yml --jq .name                 # 200                 (AC-1)
grep -nE 'ubuntu-latest|@main|@master' .github/workflows/ci.yml             # no output           (AC-1)
grep -nE '^  (lint|test|build-image|deploy):' .github/workflows/ci.yml      # 4 job ids           (AC-2)
gh run view <pr-run-id> --log | grep -c 'pushing manifest'                  # 0                   (AC-3)
gh run view <main-run-id> --log | grep 'pushing manifest'                   # …:<sha7>@sha256:…   (AC-3)
gh secret list -R $R                                                        # empty               (AC-5)
gh api repos/$R/actions/permissions/workflow --jq .default_workflow_permissions   # "read"         (AC-5)
gh api repos/$R/rulesets --jq '.[].name'                                    # "Protect main"      (AC-6)
```
