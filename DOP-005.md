## 1. Objective
Every piece of Blog/CMS infrastructure and every deploy step is a reviewed, idempotent, dry-runnable command from git — no console clicks, no hand-edited state.

## 2. In scope (today)
- `proops2026/iac/terraform/` — EC2 + security group + key pair (Day 20 lab); Terraform ≥ 1.6, `hashicorp/aws ~> 5.0`.
- `proops2026/iac/ansible/playbook.yml` — configures nginx on that host.
- `proops2026/scripts/` — `deploy.sh` (`--dry-run`, commit-SHA image tags), `healthcheck.sh`, `log-monitor.sh`.

## 3. Out of scope (for now)
- Terraform for EKS (decided Day 26).
- Terraform Cloud / Atlantis.

## 4. Acceptance criteria (draft)

| # | Criterion | Status |
|---|---|---|
| AC-1 | Terraform state is remote (S3 backend + locking), never local | ACTIVE — state is local |
| AC-2 | Every state-changing script supports `--dry-run` | DONE for `deploy.sh` |
| AC-3 | Second `terraform apply` → `No changes.`; second Ansible run → `changed=0` | DONE (Day 20) |
| AC-4 | Every bash script uses `set -euo pipefail` and passes `shellcheck` | DONE for `scripts/` |
| AC-5 | Ansible inventory is generated from Terraform output, not hand-edited | ACTIVE |

## 5. Tech stack
Terraform ≥ 1.6 · hashicorp/aws ~> 5.0 · Ansible · Bash · shellcheck
