## 1. Objective
Every piece of Blog/CMS infrastructure and every deploy step is a reviewed, idempotent, dry-runnable command from git — no console clicks, no hand-edited state.

## 2. In scope (today)
- `proops2026/iac/tfstate-bootstrap/` — S3 state bucket: versioned, AES256, public access blocked, `prevent_destroy`; the one stack with local state (chicken-and-egg). Day 25.
- `proops2026/iac/modules/aws_ec2/` + `iac/{dev,test}/` — facade over `terraform-aws-modules/ec2-instance/aws ~> 5.6`; one dir per env, same `main.tf`, values in `terraform.tfvars`, state key per env. Day 27.
- `proops2026/iac/github-oidc/` — IAM roles for the IaC pipeline (IRD-011 D11). Day 28.
- *Proposed (Day 28):* `user-service/iac/` (same module + `dev/test/prod`), run by the platform's `reusable-iac` (DOP-006 §2).
- `proops2026/iac/terraform/` — Day 20 lab (EC2 + SG + key pair + ECR); `iac/ansible/`; `scripts/` (`deploy.sh --dry-run`, `healthcheck.sh`, `log-monitor.sh`).

## 4. Acceptance criteria

| # | Criterion | Status |
|---|---|---|
| AC-1 | Terraform state is remote (S3 backend + locking), never local | DONE for Day 25+ stacks: S3 + `use_lockfile` (Terraform ≥ 1.10), one key per stack/env. Exceptions: `tfstate-bootstrap` (by design), Day 20 `iac/terraform/` (local, lab only) |
| AC-2 | Every state-changing script supports `--dry-run` | DONE for `deploy.sh` |
| AC-3 | Second `terraform apply` → `No changes.`; second Ansible run → `changed=0` | DONE (Day 20); Day 27 `aws_ec2` re-plan `No changes` after the SG `[]`→`null` fix |
| AC-4 | Every bash script uses `set -euo pipefail` and passes `shellcheck` | DONE for `scripts/` |
| AC-5 | Ansible inventory is generated from Terraform output, not hand-edited | ACTIVE |
| AC-6 | Every resource is named `{prefix}-{project}-{env}-{type}-{region_code}-{purpose}` and carries `Project, Environment, ResponsibleParty, Owner, Email` + `Name, ApplicationRole, SensitiveData` | DONE for `aws_ec2` (Day 27: `proops-blogcms-dev-ec2-use2-api-server`, 8 tags verified, destroyed). Standard to write in IRD-010 |
| AC-7 | Infra changes are planned on the PR and applied only from `main` by CI, with no AWS keys | PROPOSED — DOP-006 AC-12, IRD-011 D11 |
